## 4. 관리자 그룹 매칭 기능 (운영자 관점)

* **기능 설명:** 관리자가 버튼 하나로 수집된 백엔드 크루 데이터를 분석하여 최적의 JD 분석 스터디 조를 자동 편성하는 기능입니다.
* **상세 요구사항:**
* **관리자 대시보드 (`/admin`):** 현재까지 신청 완료한 크루원들의 명단을 표(Table) 형태로 실시간 모니터링합니다. 이 페이지는 오직 관리자 세션이 있을 때만 접근 가능합니다.
* **매칭 알고리즘 트리거:** 대시보드 하단의 **[그룹 매칭 시작]** 버튼을 누르면 작동합니다.\
  
### **매칭 규칙 및 점수 산정 방식 (우선순위):**
1. **1순위 (목표 기업 일치 - 최고 가중치):** `target_company`가 정확히 일치하거나 문자열이 유사할 경우(예: '당근'과 '당근마켓') 가장 높은 궁합 점수인 `+100점`을 부여합니다.
2. **2순위 (핵심 기술 키워드 일치 - 중간 가중치):** `interest_keywords`를 쉼표(`,`) 기준으로 파싱한 뒤, 크루 간에 서로 겹치는 기술 키워드(예: MSA, Redis, Querydsl 등) 1개당 `+20점`씩 점수를 누적합니다.


### **조 편성 및 낙오자 처리 규칙:**
* **주류 그룹 형성:** 크루 간의 궁합 점수를 총산출한 뒤, 점수가 가장 높은 크루들부터 우선적으로 한 조(**정원 4~5명**)로 묶습니다.
* **낙오자 분산 배치:** 희망 기업이 독특하거나 기술 스택이 튀어서 매칭 점수가 낮은 '낙오자' 크루들은 따로 독립된 조를 짜지 않습니다. 이미 기업/키워드로 단단하게 묶인 주류 조들 중, 아직 정원(5명)이 차지 않은 조에 순차적으로 1명씩 균등하게 분산 배치(Round-Robin)하여 함께 스터디를 진행하도록 합니다.


* **결과 저장 및 재매칭:** 매칭이 완료되면 조별 명단과 공통 분모(키워드/기업)를 DB(`results` 테이블)에 저장합니다. 관리자 페이지에 **[매칭 결과 초기화 및 재매칭]** 버튼을 두어, 인원 변동 시 기존 매칭을 지우고 언제든 알고리즘을 다시 돌릴 수 있도록 합니다.
